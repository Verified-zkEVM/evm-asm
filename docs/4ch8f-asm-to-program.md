# 4ch8f.9 — asm-string → `Program` conversion pipeline

Bead `evm-asm-4ch8f.9`. The epic `evm-asm-4ch8f` replaces every guest routine
with a verified `Program` spliced back into Codegen via `emitProgram`, guarded
by a string-equality correspondence theorem (the RlpWalk template,
`EvmAsm/Codegen/Programs/RlpWalk.lean:79`). There are ~851 hand-written
`*Function : String` asm defs, so hand conversion does not scale. This document
describes the mechanical pipeline that does it.

## What lives where

| Piece | Location | Role |
|---|---|---|
| Generator / parser / drift-check | `scripts/asm_to_program.py` | **Offline**, outside the Lean kernel. Parses GNU-as text → `Program`, renders it, assembles both, byte-compares, emits Lean source. |
| CI drift guard wrapper | `scripts/check-asm-to-program.sh` | `check-all` over the manifest; run in CI. |
| Original-asm fixtures | `scripts/asm-fixtures/*.s` + `MANIFEST.tsv` | The verbatim hand-written asm captured at conversion time; the drift guard regenerates from these. |
| Converted `Program`s + `rfl` theorems | in-place in `EvmAsm/Codegen/Programs/*.lean` | The kernel-checked artifacts. |
| Coverage report | `docs/4ch8f-asm-to-program-coverage.md` | Regenerated by `asm_to_program.py coverage`. |

## Trust model (TCB argument)

**The parser is not trusted.** It lives entirely in Python, outside the Lean
kernel. Two independent facts carry the trust:

1. **Kernel-checked drift guard (Program ↔ emitted string).** Each conversion
   lands a theorem
   ```lean
   theorem fooFunction_eq_prog : fooFunction = "foo:\n" ++ emitProgram foo_prog := rfl
   ```
   This holds by construction (the def *is* that render) and is checked by the
   Lean kernel — `#print axioms` shows only `propext`. It pins the emitted
   guest string to the structured `Program` value: any later hand-edit that
   drifts the string away from `emitProgram foo_prog` fails to typecheck. This
   is exactly the guarantee the landed RlpWalk / `*SAsm` splices carry.

2. **Offline byte-identity of the guest binary.** The conversion *changes the
   string content* — `emitProgram` renders the canonical form (`xNN` registers,
   one instruction per line, `beqz`→`beq …, x0`, `ret`→`jalr x0, 0(x1)`,
   PC-relative `.+N`/`.-N` branch offsets, comments stripped). What must NOT
   change is the **assembled guest binary**. The generator assembles both the
   original hand-written text and the `emitProgram` render with
   `riscv64-unknown-elf-as -march=rv64im`, extracts `.text` with `objcopy`, and
   requires the byte streams to be **identical**. A conversion is only landed if
   this passes; the CI drift guard re-runs it from the saved fixtures.

Neither fact trusts the Python. Fact 1 is pure kernel `rfl`. Fact 2 is ground
truth from the real assembler. The reviewer re-runs
`scripts/check-asm-to-program.sh` to reproduce fact 2 for every landed function.

**Closing the `py_emit` gap.** The `rfl` theorem is definitionally trivial (the
def *is* `emitProgram foo_prog`), so it never cross-checks the Python mirror
`_render_to_asm` against Lean's `emitInstr`. To keep the mirror out of the
trust chain entirely, the authoritative gate (`check-all` / `check-file`)
assembles the **actual Lean-rendered string** — obtained by running the real
elaborator over the manifest modules (`lean_render`, a generated
`lake env lean --run` snippet that prints each converted def) — against the
saved original-asm fixture, and requires byte-identical `.text`. This exercises
Lean's `emitInstr`, not the Python. `py_emit` remains only a fast **offline
pre-flight** (so `rewrite`/`check` need no Lean build); a `py_emit` ≠
`emitInstr` divergence can no longer pass the gate, because the gate assembles
the Lean render, not the `py_emit` render.

## The 4-byte-per-`Instr` model

`Program` execution advances `pc` by 4 per `Instr` and stores branch/jump
targets as **signed byte offsets** (`BitVec 13` for branches, `BitVec 21` for
`JAL`). For the model's byte layout to coincide with the assembled binary,
**every instruction must occupy exactly 4 bytes**. This is automatic for every
`Instr` constructor *except* `LI`: `emitInstr` renders `.LI rd c` as the GNU-as
pseudo `li rd, c`, which the assembler expands to 1–6 machine instructions
depending on `c`. When `c` fits in signed 12 bits (`[-2048, 2047]`) the
expansion is a single `addi` = 4 bytes and the model is faithful.

The generator therefore **refuses** any `li rd, C` with `C` outside 12-bit
signed range and reports the function `NEEDS-LI-EXPANSION`. A later wave will
emit the explicit multi-instruction expansion (`lui`/`addiw`/`slli`/`addi` as
separate `Instr`s), which restores the 4-byte invariant *and* still assembles
identically (`emitInstr` renders real mnemonics that `as` encodes the same way
the `li` pseudo would).

## Normalization policy

Per the bead, the Codegen string def is ours to rewrite (option (a) — normalize
the def to the rendered form; no change to `emitInstr` conventions, which are
shared by all landed splices). The parser applies these normalizations, each of
which is **encoding-preserving** (verified by the byte-compare):

| Source form | Normalized `Instr` | `emitInstr` render | Same encoding? |
|---|---|---|---|
| ABI names (`sp`, `a0`, `t0`, `zero`, `fp`) | `.x2/.x10/.x5/.x0/.x8` | `x2`, `x10`, … | yes (same reg #) |
| `label: insn` on one line; `;`-joined lines | split into separate `Instr`s | one per line | yes |
| `# …` comments, blank lines | dropped | — | yes (no bytes) |
| `ret` | `.JALR .x0 .x1 0` | `jalr x0, 0(x1)` | yes |
| `j L` | `.JAL .x0 off` | `jal x0, .+N` | yes |
| `beqz rs, L` / `bnez rs, L` | `.BEQ/.BNE rs .x0 off` | `beq/bne rs, x0, .+N` | yes |
| `bgtu a,b,L` / `bleu a,b,L` | `.BLTU/.BGEU b a off` (operands swapped) | `bltu/bgeu b, a, .+N` | yes (bgtu ≡ bltu-swapped) |
| `bltz/bgez/blez/bgtz`, `seqz/snez/sltz/sgtz`, `not/neg/mv/sext.w` | canonical base op | as rendered | yes |
| symbolic branch/jump target `L` | signed byte offset `4·(idx_L − idx_branch)` | `.+N` / `.-N` | yes (if 4-byte model holds) |

The full pseudo-expansion table is in `render_insn`
(`scripts/asm_to_program.py`). Every row is validated per-function by the
assemble+`cmp` gate — the table is not trusted on its own.

## Label / offset resolution

Two passes over the tokenized asm: pass 1 assigns each real instruction a byte
address (`+4` each, with the `LI`-size guard above) and records
`label → address`; pass 2 resolves each branch/`jal`/`j` target. Symbolic
targets become `address(target) − address(branch)`. Explicit PC-relative forms
(`.+N`, `.-N`, `.`) are taken verbatim. A target that is neither a local label
nor a PC-relative form fails loudly — see the operand-representation decisions
below.

## Symbol operands (`la`, cross-function `jal`) — representation

**Pinned by the bead: not resolved in this bead.** `la reg, symbol` and
cross-function `jal ra, <callee>` require a concrete address that only exists in
a linked image; the authoritative linker-pinned address table is bead
`evm-asm-4ch8f.6`'s deliverable.

- `la reg, symbol` — the generator refuses it (`BLOCKED_ON_.6`). Beyond the
  missing address, `la` is *position-independent* (expands to
  `auipc`+`addi` = 8 bytes) whereas the pinned `LI reg, const` would be
  absolute and a different length, so it is **not** an encoding-preserving
  substitution — it genuinely needs the `.6` layout model and its own
  byte-identity story (or a splice that keeps `la` in a thin wrapper).
- cross-function `jal ra, <callee>` / `call` / `tail` — refused
  (`BLOCKED_ON_.6`): the target offset is only known once callees are laid out
  in the linked image. These are the "call-composition" tier (bead
  `evm-asm-tj9ts`); they additionally need a call/return `cpsTriple` combinator
  and the callee's spec, tracked separately.

Local control flow (`j .L…`, `beqz … .L…`, `bne … .L…`) is fully resolved here.

## Coverage (851 `*Function` defs)

See `docs/4ch8f-asm-to-program-coverage.md` for the full table. Headline:

| Class | Count |
|---|---:|
| CONVERTED-CLEAN (byte-verified, landable) | 111 (+16 landed = 127) |
| BLOCKED_ON_.6 (`la` / cross-function call) | 550 |

| ALREADY-STRUCTURED (`emitProgram`) | 23 |

`CMP-DIFFER` is **0** — every function that parses assembles byte-identically.

## Sample landed in this PR (16)

`U256.lean` (10: the full u256 BE arithmetic/compare family — straight-line,
loop-bearing, and branch-heavy leaves), `MptSet.lean` (`msetMemcpyFunction`,
byte-copy loop), `Bloom.lean` (4: `bloomOrInto`/`bloomEq`/`runningBloomZero`/
`runningBloomCopy`), `MptEncode.lean` (`nibblesCommonPrefixLen`, loop+branch).
Each ships `foo_prog : Program`, the def rewritten to `emitProgram foo_prog`,
the `rfl` correspondence theorem, and `#guard` length pins.

The sample is drawn entirely from CONVERTED-CLEAN because the call-composition
and `la`-using classes are `BLOCKED_ON_.6`; they land once the `.6` address
table exists.

## Follow-up waves (file child beads)

1. Convert the remaining **111** CONVERTED-CLEAN leaves (mechanical; batch by
   file).
2. **NEEDS-LI-EXPANSION** (20): teach the generator the explicit `li` expansion,
   then convert.
3. **BLOCKED_ON_.6** (550): after `evm-asm-4ch8f.6` publishes the address table,
   resolve `la`→`LI`/region pointers and cross-function `jal` offsets (the
   latter also needs the call-composition combinator, bead `evm-asm-tj9ts`).
4. **CALLER-LOCAL-FRAGMENT** (8): extract a callable status-returning ABI first.

## Reproduce / re-run

```sh
# convert one function and eyeball the Program
python3 scripts/asm_to_program.py emit-lean --file EvmAsm/Codegen/Programs/U256.lean --func u256IsZeroFunction

# byte-identity check for one function
python3 scripts/asm_to_program.py check --file EvmAsm/Codegen/Programs/U256.lean --func u256IsZeroFunction

# in-place rewrite (saves fixture + manifest entry)
python3 scripts/asm_to_program.py rewrite --file <file> --funcs "aFunction,bFunction"

# CI drift guard over all landed conversions
scripts/check-asm-to-program.sh

# regenerate the coverage report
python3 scripts/asm_to_program.py coverage
```
