## Boundary chosen

Whole-item: `rlp.decode` / `rlp.encode` against `EL.RLP.decodeFully` /
`EL.RLP.encode`. **Not** exercised: `decode_item_length` (the cursor-advance
primitive) and the typed `deserialize_to` layer — rows resting on those are
graded `inspection`, not `diff`. See [§Numbers](#numbers-strictness-varies-by-field-type).

## Why the question is tractable here

`SpecRef` never ported RLP — it **imports `EvmAsm.EL.RLP` verbatim**
(`docs/4ch8f-specref-port.md:36`), and the guest decoder proofs bridge to that
same model (`EvmAsm/Rv64/RLP.lean:6`). One shared definition serves both towers:

```
ethereum_rlp 0.1.6        (external package, not vendored)
      │  executable differential — 3757 records, 0 divergences
      ▼
EvmAsm.EL.RLP  (encode / decodeFully)        ← shared model
      ▲                          ▲
      │ imported verbatim        │ bridge lemmas (per routine — see Gaps)
SpecRef.*                 Rv64.RLP.* / Codegen.Programs.Rlp*
                                 ▲
                          guest RISC-V routines
```

## Numbers: strictness varies by field type

Integers are **not** validated by the RLP codec. `rlp.decode` treats an
integer-shaped payload as an ordinary byte string and accepts it — the corpus
pins this (`820001`, `89·ff×9`, `a1·ff×33` all `accept`). The rules live one
layer up in `_deserialize_to_uint` (`rlp.py:265`):

1. **leading-zero rejection** — uniform across every field type;
2. **width rejection** — via `class_.from_be_bytes`, and this **differs per
   field**, because the target type is chosen per field:

| Target | Cap | Example fields (`forks/amsterdam/blocks.py`) |
|---|---|---|
| `Uint` | **none** | `difficulty:152`, `number:157`, `gas_limit:162`, `gas_used:178`, `base_fee_per_gas:203` |
| `U64` | 8 bytes | `blob_gas_used:218`, `excess_blob_gas:226`, `slot_number:263`, `Withdrawal.index:46` |
| `U256` | 32 bytes | `timestamp:183`, `Withdrawal.amount:62` |

So `rlp_content_to_u64` (status 2 on `len > 8`, status 3 on a leading zero)
matches `_deserialize_to_uint` at `U64` **exactly**, and is **stricter than the
reference on a `Uint` field**, where a 9-byte value is legitimate. That is a
per-call-site obligation, not a routine defect.

## Gaps and follow-ups

Divergences found: **none.** The rest is coverage and hygiene.

1. **Inheritance bridges** for the remaining `machine-only` rows
   (`rlp_content_to_u256_be`, `rlp_list_count_items`, `withdrawal_decode`) — see
   method §4, and GH #11341. A drift between the local predicate and `EL.RLP` would
   be invisible to both the differential and the proof.
   - ✅ `rlp_bytes_encoded_size` — `rbesSize_eq_encodeBytes_length`
     (`Codegen/Programs/RlpBytesEncodedSizeBridge.lean`).
   - ✅ `rlp_list_encoded_size` — `rlesSize_eq_encode_list_length`
     (`Codegen/Programs/RlpListEncodedSizeBridge.lean`), which also had to *name*
     the formula (`rlesSize`): the machine theorem stated it inline, so there was
     nothing to compare against the reference.
   - Both rest on `u64ByteLen_eq_toBytesBE_length` — the guest's 9-way
     length-of-length ladder IS `(Nat.toBytesBE ·).length` — proved once for the
     first and reused by the second.
   - Of the three left, `withdrawal_decode` is the one whose model side is mostly
     built already (`EL.decodeWithdrawal`, `EL/Withdrawal.lean:46`, plus five helpers
     at `Rv64/RLP/WithdrawalDecode.lean:1143-1219`); the obstacle there is that those
     helpers belong to the *other* withdrawal-decode effort — see the warning above.
2. **Typed-layer oracle** covering `_deserialize_to_uint` at `Uint`/`U64`/`U256`,
   moving the scalar rows from `inspection` to `diff`.
3. **Call-site type audit** — every guest site decoding a header/withdrawal
   field must pair the field's Python type with the matching routine; a `Uint`
   field decoded by a `_to_u64` routine is a latent false-reject.
4. `rlp_prefix_to_buffer` has **no drift guard**, unlike every other emitted RLP
   routine — the string↔`Program` tie is missing entirely.
5. Stale docstring `Codegen/Programs/RlpSpliceHelperSpec.lean:25,38` names two
   theorems that do not exist.
6. `EvmAsm/Rv64/RLP.lean` header calls Phases 2/5/6 "planned"; both have landed
   modules.
7. `docs/4ch8f-guest-image-coverage.md` addresses are stale vs `GuestAddrs.lean`.
8. `EvmAsm/Tests/RlpDiffCheck.lean:26` cites a nonexistent
   `scripts/rlp-check-all.sh`; `rlp-diff-check` is still not built in CI.
9. SpecRef pin disagreement: `SpecRef.lean:5` v0.4.0,
   `docs/4ch8f-specref-port.md:4` v0.5.0, `SpecRef/Ssz.lean:5` v0.6.0 — gitlink
   is v0.6.2.

## Reproduce

```bash
git submodule update --init execution-specs
git -C execution-specs describe --tags        # expect tests-zkevm@v0.6.2

uv pip install --target /tmp/rlp ethereum-rlp==0.1.6
PYTHONPATH=/tmp/rlp scripts/spec-oracle.py --family rlp --check

lake exe correspondence-check rlp --self-test
lake exe correspondence-check rlp
```

The checker imports only `EvmAsm.EL.RLP.FullDecode` (closure: `Decode`, `Basic`
— no Mathlib), so it builds in seconds; CI replays the committed corpus and
never needs Python.
